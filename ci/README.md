`run-ci.sh` 是 gitea Actions(`.gitea/workflows/gen.yml`)调的那个脚本,
跑在 .64 的 host executor 上,以 `lo` 身份执行。

    .64:  /home/lo/ci/run-ci.sh  ->  /home/lo/ci/hi-proto/ci/run-ci.sh   (软链)
          /home/lo/ci/smoke      ->  /home/lo/ci/hi-proto/smoke          (软链)

**改脚本改仓里这份并提交**,别在 .64 上就地改 —— 否则又变回"两份各自漂"。

## 什么样的 push 才会产 tag

**判据只有一条：生成物变了才有新号。**（2026-08-18 加路径过滤，2026-09-05 一度改成
「每个 dev 提交都要有号」，2026-09-10 改回内容判据 —— 见下面「为什么」。）

具体是两层，**结论由第二层给出**：

| 层 | 看什么 | 作用 |
|---|---|---|
| ① 路径过滤 | 改动有没有落在 `*.proto`、`codegen/`、`http/`、`buf.yaml`、`buf.lock`、`Makefile`、`release.sh` | 只用来**省掉那趟生成**（整轮里最慢的一段），不决定打不打号 |
| ② 内容判据 | `release.sh` 跑完之后 **hi-proto-code 的 dev 有没有往前走** | **决定打不打号**：没往前走 = 没有新东西可发布 → 不打 |

参照点是**本分支上最近一个 CI 打的 tag**（水位线）；tag 是整轮最后才推的，中途失败下一轮会重跑。

- **`main`（正式发布）不受这条约束** —— 发版必须出号，哪怕这一版与上一个 dev 号一模一样。
- **推基号（只动 `VERSION`）不产 tag。** `release.sh` 压根不读 `VERSION`（基号只用来拼 tag 名；
  生成物里没有基号，rust crate 的 `version` 写死 `0.1.0`），所以生成物一个字节都不变。
  **这是预期行为，不是漏打** —— 要等下一个真正改到生成物的提交才出 `vX.Y.Z-dev.1`。
- 路径在触发集里、但生成物其实没变（比如只动了不进生成物的那部分注释）—— **同样不打号**。
  这一档路径过滤兜不住，靠的就是第二层。

### 为什么判据是「生成物」，不是「推没推 dev」

**号的意义是「这里有一份新的生成物可以取」。** 它一旦可以为空，新号就不再意味着任何事。

2026-09-10 实测的样子：刚发完正式版 `v1.5.14`，紧接着推基号，CI 就蹦出一个
`v1.5.15-dev.1` —— 而它在 hi-proto-code 那边指向的是**和 `v1.5.14` 同一个 commit**。
同事看见新号只会以为「又更新了」，去 diff 才发现一个字没改。

老规矩「没打 tag 的提交消费方根本够不着，等于没发布」**没有被推翻** —— 它讲的是**够不着**。
生成物没变时，消费方钉上一个号拿到的就是一字不差的同一份代码，不存在够不着。
两者本来不冲突：**该打号的判据是「生成物变没变」，不是「推没推 dev」。**

（三个手工打 tag 的库 —— `hidid-core` / `hiclub-core-mqtt` / `hinj-plugin-sdk` ——
不适用这条：它们没有 CI 去比对生成物，推了 dev 就得打，见 CLAUDE.md。）

### 顺带解决的老问题

只改 `smoke/` 也照样产 tag，于是历史上出现过两串同指一个 commit 的 tag：

```
v1.5.0-dev.166 / .167 / .168  → 生成物 c2faf3e4
v1.5.1 / v1.5.1-dev.1 / .2    → 生成物 563f7e58
```

后果不是「多几个 tag 不好看」：

1. 下游每次都得停下来判断「这个新号要不要跟」，答案几乎总是「不用」—— 判断成本全白付；
2. `deps.md` 为此专门备案了一节（「三个 tag 同一个 commit，不用跟」）；
3. 最糟的是它训练出**「新 tag 大概率是空的」**这种直觉 —— 真正该跟的那一次会被一起忽略。

### 改这个脚本时注意

**改动从下一轮 push 起才生效。** 脚本会先 `git reset --hard` 把自己更新掉，但 git 换的是
inode、运行中的 bash 手里还攥着旧 fd，所以**本轮跑的是上一版脚本**。
加过滤那次就多产了一个 `v1.5.2-dev.2`（旧脚本执行的），属预期。
